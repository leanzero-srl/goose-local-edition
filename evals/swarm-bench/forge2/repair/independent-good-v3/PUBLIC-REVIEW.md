Read the whole changed `index.js`, `ledger.js`, `pending.js`, `search.js`, `sync.js`, their complete backend consumers, configuration/discovery, budgeting, realtime, UI sources/shared bridge, manifest, package/build definitions, and the author's complete public controls. The authoritative entrant material was the five public files specified by the parent. The pinned read-only SDK was inspected directly.

`app/src/pending.js:9–13` reads the strongly consistent work key, unions the sprint obligation and executes it with the caller's mutation: `transaction.set(REFRESH_WORK, { sprintIds, startAt: 0 }).execute()`. A ledger/member mutation therefore cannot successfully commit through this helper without the refresh obligation committing in that same transaction. `app/src/ledger.js:36–43` routes row creation, metadata update and member saves through that helper. Row creation preserves its `FAIL_IF_EXISTS` option. Every such call in event processing, deletion, migration and CI deployment updates was followed to its caller (`sync.js:34,50,64–65,111,125`). No alternate writer of these ledger/member objects was found.

`app/src/sync.js:8` supplies `concurrency:{key:'scope-background',limit:1}` on the shared enqueue door. Product and deletion triggers, scheduled reconciliation, continuation jobs and deployment work all use that door. The public contract §8 says a key applies “across all queues in this installation.” The CI web trigger writes its separate deployment receipt and queues ledger updates; it does not write refresh work or ledger members. The feared read/union/write race and refresher/delete race therefore require a writer outside the serialized door, which the current tree does not contain.

`app/src/index.js:24,30` invokes `refreshPrecomputations(background)` before and after the body. On an idempotent redelivery, the pending obligation is drained before row-exists checks can skip mutation. Its `RateLimited` catch returns the actual SDK `InvocationError` response with retry information. The body is not the only owner of its previously committed refresh.

`app/src/search.js:17–38` waits five seconds before index reads, persists the current precomputation page before generating or posting fragments, advances `startAt` only after a successful POST, and clears work only after the final page and announcement. A failed POST or interruption before acknowledgement leaves work/page replayable. Successful POST followed by interruption can repeat the idempotent POST. A five-second wait after obtaining the serialized slot covers writes from the prior invocation, including a killed one; a query is not trusted immediately after its mutation.

The actual `@forge/kvs 2.0.7` runtime implements the four-argument `set(key,value,entity,options)` in `out/transaction-api.js:16–28`, passes mapped operations to `storageApi.transact` at lines 55–64, and sends `/api/v1/transaction` in `out/storage-api.js:98–99`. `out/utils/transaction-request-builder.js` forwards `entityName` and options. The changelog explicitly includes key-policy support in transactions. The narrower declaration of `SetOptions` does not establish a runtime rejection; native public calls accepted the two-operation transactions. Each helper transaction has one mutation and one work-key set, below the contract's 25-operation bound. Actual `@forge/events 3.0.7` queue/concurrency and retry builders were also inspected and used by the controls.

## Refuted suspicions and limits of each refutation

1. **Committed row skips refresh on retry: REFUTED for V3.** A V2 control with the same expansion-changing public transport scenario retains the new row/member yet never refreshes on idempotent retry. V3 retains pending work atomically and drains it before the retry body. The control is meaningful because V2 fails the expected freshness assertion and V3 passes it; it is not a test that merely counts writes.
2. **Incomplete writer coverage or installation-wide concurrency race: REFUTED.** The whole-tree writer/caller trace above and the actual SDK queue payload show the common key on every dispatch. Unkeyed concurrent writers are not constructible from the shipped handlers. Arbitrary direct calls to exported internal helpers would not be the installed path.
3. **SDK options/transaction-size incompatibility: REFUTED.** Actual runtime construction and native two-operation transaction successes contradict it. A native platform atomic rollback or actual invocation kill during a transaction was not tested here; the pure transport scenarios model the public atomicity contract.
4. **Lost page on POST refusal or time refusal: REFUTED in the covered sequences.** The page checkpoint is written before fragment work; POST success precedes cursor acknowledgement. Independent tests cover refusal during fragments and interruption after POST, in addition to the author's continuation cases. The 101-clause synthetic page case is a transport pagination test, not proof of that many real shared native clauses.
5. **Cursor invalidation/expiry race: NOT CONSTRUCTIBLE in the disclosed six-hour cohort.** The public cache lasts seven days; newly added clauses are computed from current ledger after the visibility wait, while ledger writers are serialized. The contract does not specify arbitrary destructive reordering of precomputation pages. This does not assert safety under undocumented deletion/reordering of already listed clauses.
6. **Already-closed sprint 770 returns `Unknown sprint`: REFUTED as a confirmed contract violation.** The public dev call really returned the error for a historical sprint, but it was not shown to belong to the active-at-upgrade/newly-started known-plan cohort. Contract §3 requires backfill since each active sprint started; §5 explicitly opens sprints active at upgrade, including one that closes later. §19's “Active and closed sprints retain their history” does not establish that an already-closed-before-upgrade sprint with no populated v2 history is required to receive a new ledger. An error alone cannot prove that cohort. This observation was withdrawn, not sent as a defect to the author. A later native qualification must test a sprint that actually closes during the required cohort.
