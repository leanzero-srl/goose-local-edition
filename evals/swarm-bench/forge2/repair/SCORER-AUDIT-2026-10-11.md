The six published builds used the same scorer and kit hashes. Their shared high component results are genuine outputs of that scorer; the audit does not establish that MiMo's app was inferior to Sol's. MiMo earned 0.9757 inner × 1.0 critical × 0.8671 reliability = 0.8461; Sol earned 0.9845 inner × 1.0 critical × 0.8238 reliability = 0.8111. Both had an empty observed/unsuppressed critical list. R1, R3 and R8 each received full credit on all six. The raw saved sources, model costs, receipts and observations were read from `/private/tmp/forge2-audit-evidence/`.

The prior scorer's most consequential confirmed defects were compound controls: when every admin action failed, an observed non-admin write was called vacuous; when valid CI had no effect, an unsigned write was called vacuous; when no v1 row reached v2, complete deletion of the v1 source was called vacuous. All three now price observed harm before the positive-control gate. Refusing every legitimate request still earns nothing.

The migration row formerly compared identity and time only. Its source observations omitted kind, issue, author and source. The probe now preserves the source payload; the scorer compares all source attributes for source preservation and the contract's preserved attributes for the v2 copy. Additional v2 attributes are permitted. Attributes missing from historical source observations are never invented. A source loss or corrupted authoritative copy fires the migration critical; an intact source with no migrated feature is unearned but does not fire it.

The old R8 tool row measured writes, although `report_scope` primarily returns text and citations. Its cache row could pass when both clicks made zero calls and merely displayed an error. The repair records each click's actual summary/citation DOM, flags, offered and returned function, finish reason and virtual request timestamps. A successful clean answer must really paint its returned citations before negative scope controls can pass. A cache must serve the same successful summary and citations on the second click with no call. A second viewer is exposed to the primed cache within its lifetime on a sprint whose browse permissions differ. Hidden citations and issue keys fail that control. A scripted unsolicited function exercises rejection in both chat and stream. Error cases must reach their intended scripted answer, display the required error flag, and show neither unfinished content nor an immediate retry storm. Old archives lacking this new observation evidence are unavailable for those rows, not hypothetical app failures.

CI originally sent every case serially despite a concurrent replay guarantee. The repaired drive starts two identical signed events in a deterministic group. The winning input seat is unspecified: the status multiset must be 200 and 202 with distinct attributed invocations. Both attributed invocations writing ledger data fire the duplicate critical even when last-writer-wins storage looks singular. Two 202 responses fail replay/status credit; responses alone never prove duplicate business harm. A single business application with wrong response labels does not fire that severe-defect multiplier. Sequential replay writes and repeated environments are inspected before any valid happy-path gate.
