Build a CLI persistent string index "trie" in Rust (cargo, no networking) backed by a file in a dir (global --dir, default .trie). Model: a prefix tree (trie) of key->value string pairs, persisted (serialize the trie to the file on write, load on start; an append-only op log is also acceptable as long as replay rebuilds it). EXACT commands: 'trie init'; 'trie set KEY VALUE' (insert/overwrite); 'trie get KEY' (print the value; non-zero if absent); 'trie del KEY' (remove; non-zero if absent); 'trie has KEY' (exit 0/non-zero, print yes/no); 'trie prefix P' (print all key\tvalue pairs whose key starts with P, sorted by key); 'trie range LO HI' (print all key\tvalue pairs with LO <= key < HI, sorted); 'trie keys' (all keys sorted); 'trie count [--prefix P]' (number of keys, optionally under a prefix); 'trie longest-prefix S' (print the longest stored key that is a prefix of S, or non-zero if none). Validate inputs; exit non-zero on a missing store or absent key. Integration test (tests/): init; set several keys; get/has/del; prefix returns the right sorted subset; range is half-open and sorted; longest-prefix works; count with and without a prefix; and that persistence survives (reopen and the data is still there). Provide Cargo.toml. Target ~1000-1400 LOC (trie, persistence, commands, cli).
