Build a CLI persistent job queue "jq" in Rust (cargo, no networking) using an append-only log file in a store dir (global --dir, default .jq). Model: each enqueue/claim/complete/fail is an append-only record; an in-memory state is rebuilt by replaying the log on startup. EXACT commands: 'jq init'; 'jq push PAYLOAD [--priority N]' (append a job with a new integer id, print the id; default priority 0); 'jq peek' (show the next ready job - highest priority then oldest - without claiming); 'jq claim --worker W' (atomically mark the next ready job in-progress for worker W, print its id+payload; non-zero if none ready); 'jq done ID' (mark a claimed job complete; non-zero if not in-progress); 'jq fail ID [--requeue]' (mark failed; with --requeue put it back to ready with an incremented attempt count); 'jq list [--state ready|in-progress|done|failed]'; 'jq stats' (counts per state); 'jq compact' (rewrite the log keeping only the latest record per job; behaviour identical after, file smaller when there were state changes). Validate inputs; exit non-zero on missing store, unknown id, or a bad transition. Include an integration test (tests/): init; push several; peek respects priority; claim/done/fail/requeue transitions; list+stats reflect them; compact shrinks the log and preserves state. Provide Cargo.toml; build+run with cargo. Target ~1000-1400 LOC (log, state, commands, cli).
