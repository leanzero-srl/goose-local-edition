Build a CLI "jsonq" in Python that runs a small JSONPath-like query over a JSON file — implement the path engine yourself (do NOT use jsonpath libraries). EXACT commands: 'jsonq get FILE "PATH"' (print the matched value(s) as JSON, one per line); 'jsonq keys FILE "PATH"' (for an object match, print its keys). The PATH language, which you must TOKENIZE and PARSE: starts with $, then a sequence of: .name (child), ["name"] or [index] (bracketed child/index), [*] (all elements/values), [start:end] (array slice), and a filter [?(@.field OP value)] where OP is = != < <= > >= comparing a child field to a number or 'single-quoted string'. Support chaining (e.g. $.users[*].name, $.items[?(@.price > 10)].id). numbers compare numerically; a missing field in a filter never matches (never crash). Exit non-zero with a clear message on a missing file, a malformed JSON, or a path parse error (report the position). Runnable as 'python -m jsonq'. pytest suite over a fixture JSON: child access, array index + slice + wildcard, a filter with numeric and string comparison, a chained path, and that a bad path and a missing file exit non-zero. Target ~900-1300 LOC (tokenizer, parser, evaluator, cli).
