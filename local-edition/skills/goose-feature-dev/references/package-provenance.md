## Incremental Rust-only staging (2026-10-27)

A new tested CLI does not require rebuilding an unchanged desktop UI or re-signing every unchanged nested file. First prove zero UI source diff and the new executable's exact gated source/hash. Extract the immutable, notarized baseline archive into a fresh private staging directory; never patch the installed app or overwrite the previous delivery archive. Fingerprint every file's bytes, modes, symlinks and extended attributes. Sign only the replaced CLI, then the outer app with explicit preserved identifier, entitlements, requirements, flags, runtime and constraint metadata. Do not use `--deep` while signing; use it for verification.

Verify the newly signed CLI against its gated input and the Electron main executable against its baseline using the narrow Mach-O equivalence check. Require every other bundle fingerprint to remain identical; only the CLI, main executable signature and root `_CodeSignature/CodeResources` may change. The real incremental stage took 34.88 seconds with exactly those three changes and all nested signatures preserved. A new notarization is still required: re-check the entire signed fingerprint before upload, staple the accepted ticket, require only `Contents/CodeResources` to change during notarization, then verify strict signature/staple/Gatekeeper and make a fresh metadata-preserving archive. Real normal-launch/profile verification remains a separate rollout gate. The project procedure and executable guard scripts live under `docs/ios-release/desktop-controller-candidate/`.
