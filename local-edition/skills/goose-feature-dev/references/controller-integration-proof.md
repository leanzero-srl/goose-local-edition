# Controller integration lessons — 29 October 2026

An output revision is not automatically a control-state change. Chat streaming rewrites partials; external job log growth also advances the catalog. Do not disable revision checks or accept every log_updated event. Prove an anchored same-work, same-run interval containing only output, with all control metadata unchanged. Legacy log_updated can also hide simultaneous semantic changes. Only the catalog writer may attest a pure append after complete source-metadata comparison and known strictly increasing byte lengths. Admission and dispatch share the same rule. Missing history, run/generation changes, truncation and unknown lengths remain strict.

A typed pinned-owner stale_revision refusal before admission can release that exact unaccepted client outbox entry. Persist removal before reporting it; preserve the draft and require a new explicit action. An unknown transport outcome, accepted receipt or receipt404 by itself cannot release or change a command ID. Reopening the app must not lose the pending payload when the composer starts empty.

A named cloud node pins the main swarm reply but does not prove all helper calls are cloud-only: helper_plan may append already-serving MLX nodes. For a disposable cloud-only chat, the existing standard session/set_config_option can select direct openrouter and its model for that session, using existing credentials. Verify the live Agent/persisted session, controller sharing readback and provider endpoint configuration. Do not change global defaults or copy credentials. A missing response after a settings write requires readback reconciliation, not an automatic retry. Record the timeout separately from the verified effect.

An active-steering proof needs actual assistant words, not just running state. Read a fresh openWork snapshot after partial output begins; persist one command before sending, then check the exact receipt, one matching message, interrupted old output and the subsequent response. A delivered receipt alone is insufficient. Keep API proof and visible UI proof separate. If a model repeats trailing instructions after an unquoted “reply exactly:” prompt, retain the failed literal assertion and judge the control mechanism from the actual words; do not rerun merely to manufacture a green result.

Whole-app upgrades must bind the complete incoming bundle to the signed receipt, not only its CLI hash/version/team. Cross-Mac ZIP extraction can drop com.apple.provenance on the bundle root and symlinks even when a same-Mac roundtrip retained it. Permit only that removal while comparing every other byte, mode, link target and attribute exactly; never relax quarantine or signatures. An existing staged directory may be reused only after complete verification. An idle catalog state can still represent a waiting agent or queued shell job: any nonnull current_run_id blocks an upgrade. Keep rollback apps and profile files intact, then verify normal startup and saved-login reconnection.

## Cold controller preparation — 29 October 2026

A command can pass admission and then reject itself at dispatch if cold Agent restoration writes its saved provider or extensions back to sessions. Those writes journal session_changed even when the settings were unchanged. Test the real ACP executor preparation path, not an OwnerExecutor mock that simply returns an Agent. Preserve the revision checks at both admission and dispatch.

When normalized active provider/model equals the supplied saved Session snapshot, install runtime state without persistence. Comparing to a fresh database value and then writing the old snapshot can overwrite a concurrent edit; the original snapshot comparison avoids that. A real fallback, missing setting or normalization change still persists and remains subject to revision rejection. Loading saved extensions must retain their exact saved configuration, including failed extensions; do not replace it with a runtime HashMap’s order or its successful subset. Explicit add/remove operations own persistence.

The regression must prove unchanged cold preparation leaves the real catalog revision unchanged and delivers one command, while a concurrent external edit and genuine normalization/fallback changes reject with no model call. Include an old-snapshot restore after a newer model edit and prove the newer value survives. A rejected receipt is a durable outcome, not an unknown delivery: preserve its identity and the edited draft, make the failure visible, and never automatically resubmit it.
