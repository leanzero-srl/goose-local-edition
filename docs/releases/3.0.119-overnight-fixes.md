# 3.0.119 — the overnight fixes

## What happened

On the night of 2026-10-18/19 local and cloud benchmark runs on three Macs (the laptop, the Mac Studio and
Gabee's MacBook) were audited every hour. Each run that ended early, re-read its whole prompt every turn or
lost tool calls was traced to its layer and filed (RUN-ISSUES I-10 to I-32). The fixes were built on their own
branches; this release carries them together, with the engine the runs used.

## The fixes, by issue

Goose (the harness every entrant runs in):

- I-10: a model that calls a tool goose does not offer, with arguments that fit exactly one offered tool, runs
  as that tool (`bash` with a `command` runs as `shell`). Mistral Large 4 lost 48 Forge calls to "Tool 'bash'
  not found". Calls that fit no tool, or several, are still refused with the closest tools named.
- I-11: helper calls on OpenRouter's fast model no longer carry the entrant's host pin. Under a pin, every
  helper call failed with "No endpoints found" and fell back to the entrant. The helper model is unchanged.
- I-12: the context probe reads the window the LeanZero MLX engine serves (`max_model_len`, then
  `context_window`). Before, every run on the current engine used the default limit.
- I-13: an edit whose `before` equals its `after` is refused ("No change made"), and an empty-turn retry adds a
  short continuation note instead of resending the identical conversation, which a local model answered with
  the same one-token stop three times.
- I-15: `read_image` on a text file says the file is text and names `shell`.
- I-19: when parallel tool calls return an image, the image message goes after the last tool result. Strict
  hosts (Mistral) refused the old order with "Unexpected role 'tool' after role 'user'" and the run ended.
- I-22: the OpenAI formatter no longer folds sequential turns into one assistant message when every turn's
  reasoning is blank (Gemma 4 with thinking off). The fold rewrote the prompt from about token 2,800 on every
  call, so the engine re-read the whole prompt every turn.
- I-26: `tree` names `node_modules`, `bower_components` and `__pycache__` without listing them, and cuts a
  listing over 2,000 lines. One `tree` of a Forge run directory was 161,890 characters.
- I-31: a compaction keeps the person's request as the chat's latest request, never goose's own "your last
  reply was cut off" note. Preserving that note ended a run at call 54 of 300.
- Benchmark publish (owner's request): the app names a cloud entry by its model, sends the run's own
  OpenRouter bill (or the prices the publisher declares when there is no bill), sends a Forge 2.0 build's
  comparison cohort so the two builds of a model couple into one entry, and marks LeanZero's own cloud runs
  as baselines with the operator key. An older site that does not know a field gets the run without it.

The engine (Rapid-MLX v0.14.3-lz.12, fork commit cd53a8247):

- The memory guard: every prefill chunk, decode step and batch join is planned against the Mac's memory, so a
  long session cannot run out of memory, and the prefix cache keeps each conversation's newest entry.
- I-1 / I-30: local Nemotron-H and Nemotron 3.5 Bolt folders get their tool and reasoning parsers; Bolt runs.
- I-2: Xing4.0 runs. I-7: latent-attention KV is priced from what the cache stores, so Xing is no longer capped
  at 35,328 tokens.
- I-4 / I-4b: Gemma 4 reuses its prefix cache across agent turns (it reused about 10% before).
- I-17: Gemma 4's KV is priced from its attention modules (it was priced 8x too high), and a request that cannot
  fit is refused with a typed error instead of a streaming 500.
- I-23: Granite 4.2 gets its dense profile, and an explicit `--tool-call-parser` binds.
- I-29: the guard prices KV in the dtype the cache holds (Granite 4.2 had half its native window).
- I-32: a template that keeps history think blocks is not given a second copy of each one.
- lz.11's LFM2/LFM2.5 local profile is carried forward (the overnight engine line did not have it).
- Goose no longer passes the prefix-cache share to this engine: the guard sizes its cache from the device, as
  it did in the overnight runs.

## What does not change

- The benchmark kit is byte-identical to 3.0.118: no scorer, probe, fixture, threshold, contract, starter or
  harness file changed. The sb7.2 and forge2 manifests are main's, and the Forge 2.0 task fingerprint stays
  ef9776e6…, so builds from 3.0.118 and 3.0.119 publish and compare as the same task.
- The distributed Flash split runs the same pipeline engine as 3.0.118 (fork commit 8c000705). The review of
  the new engine against it lists 11 fixes the split does not have yet (fork branch lz/pipeline-review-lz12).
- The call budget (150 Gauntlet, the Forge 2.0 allowance) and the cloud entrants' requests are unchanged apart
  from I-11 (helper calls) and I-19 (message order with images).

## Not in this release

- I-25 (a refused run records `stopped_by: provider_error` instead of `model_finished`) is deferred. Its fix
  lives in `bench/run_build.py`, which the Forge 2.0 task fingerprint pins, so shipping it would make every
  earlier Forge 2.0 build unpublishable. It needs a form that leaves the fingerprint alone.
- The t12-line features in the test build on Gabee's MacBook are not here: the run's thinking effort sent to
  the local engine (reverted on main on purpose), compaction V2 and V3, the served-window re-read every minute,
  the served-window/fit/placement rework, an in-stream context overflow that compacts, the offered-tools gate,
  narration and tool call sent as one message, the LM Studio wake fix, and t12's own `tree` change (I-26 here is
  a separate fix of the same problem). None of them is reviewed against this branch.
