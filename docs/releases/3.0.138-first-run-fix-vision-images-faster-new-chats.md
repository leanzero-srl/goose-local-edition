# 3.0.138 — a first-run fix, images for vision models, and faster new chats

Everything merged since 3.0.137 (`git log v3.0.137..v3.0.138`).

## First run and nodes

- **Saving your first node makes new chats work.** After Run it > Run > Save as node with no other nodes set up,
  every new chat failed with an error about a missing `swarm` block in config.yaml. When new chats run on Any node
  (Auto) and Auto has nothing to answer them, the node you save now becomes where new chats start, and goose says
  so on the Run it row, the New node dialog and the Nodes page. If you use a cloud provider directly, saving a node
  no longer moves your chats onto the swarm.
- **No false "Restart required" after the first mount.** Mounting a model other than the one in your engine
  settings, without changing anything, showed "Restart required · Settings changed". goose now compares the settings
  with the model that is actually running, so the banner only appears when a remount would really change something.

## Safety and checks

- **goose asks before a shell command that destroys work.** Commands such as `git reset --hard`, `git checkout -- <paths>`,
  `git clean` or `rm -r` on files git cannot bring back now show a confirmation card first, in every mode unless you
  turn this off explicitly. Removing regenerable build folders inside the project (node_modules, target, dist and the
  like) still runs without asking; any other ignored folder, such as a local data directory, asks.
- **The answer check no longer flags true claims.** When a reply said "All 19 tests passed" after the test run printed
  "19 passed", the goose check called it a contradiction. It now recognises two wordings of the same result, still
  catches a negated or partly quoted claim that hides a failure, and only compares whole summary lines.

## Images and vision models

- **Vision models such as Gemma 4 see images from tools.** When a model read an image with the read_image tool, or
  you named an image by its path, the image went straight into the turn, the engine refused it as too long for one
  batch, and goose then said the model reads text only. goose now describes those images first in a short side
  request, the same way it already handled attached voice notes, so the turn stays small.
- **The right reason when an image is withheld.** If a request is still too long for the engine to take an image,
  goose now says the model reads images but this request was too long, instead of claiming the model is text-only.

## Local engine

- **New chats start faster.** The engine is now Rapid-MLX v0.14.3-lz.22. It keeps a resume point at the end of the
  shared system prompt and tools, and picks the deepest resume point it has, so a second chat with the same setup
  skips almost all of that prefill. On a MacBook a new chat resumed at 21,856 tokens instead of 20,480 and started
  in 0.65 s instead of 2.79 s. Memory use is unchanged.
- **MiMo on two Macs no longer runs out of memory when a long chat is compacted.** The split's prompt cache now counts
  the copies it is about to make against each Mac's memory plan before it makes them, so one Mac can no longer grow
  past its share and take the engine down. Both Macs of a split must run 3.0.138.
- **Long sessions stay warm again (lz.21).** In 3.0.137 one short spike in other apps' memory could lower the
  engine's memory ceiling for the rest of a session, so a long session lost its cache much earlier (167k tokens
  instead of 371k in our test). The engine now leaves its own memory out of that reading and only reacts to a level
  that holds for 15 seconds, or at once while the Mac is swapping.
