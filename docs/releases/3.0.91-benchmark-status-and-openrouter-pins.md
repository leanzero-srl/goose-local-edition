# 3.0.91 Benchmark status in the menu bar, and OpenRouter host pins that no longer hide the provider

**The menu-bar icon shows a running benchmark.**

- **While a run is live:** the title reads like `Benchmark · gpt-6.1-sol · 64/150`, with the model and the calls
  used out of the run's budget. Before any call count is known it shows the phase (preparing, building, scoring, finalizing)
  instead.
- **The menu:** it opens with the benchmark (Gauntlet 7.2 or Forge 1.0), the model (or the swarm's node count),
  the phase, the time elapsed, the calls used and an "Open Benchmark" item.
- **After a run:** the menu keeps one line until the next run starts, for example `Last benchmark: gpt-6.1-sol ·
  Gauntlet 7.2 · 79.9%`, `did not finish` or `cancelled`. It adds the billed amount when the scored result has
  one.
- **Missing values:** anything the app does not know is left out rather than guessed.

**An OpenRouter host pin no longer makes OpenRouter disappear from the Benchmark form.**

- **What happened:** with a host pin set in `OPENROUTER_PARAMETERS` (for example
  `{"provider":{"order":["xiaomi"],"allow_fallbacks":false}}`), the provider key check sent that pin along with
  your saved default model. OpenRouter answered "No endpoints found" when the pinned host did not serve that
  model, the check failed, and the Benchmark form showed "No configured providers" with no reason given.
- **The fix:** the key check now ignores routing parameters. Chats and benchmark runs still use your pin.
- **The form explains itself:** it now names each saved provider it cannot offer, with the check's own error
  text, instead of a generic message.

**Also:** the Forge benchmark's description in the Benchmark view now names its real scope: ten module types plus
the Realtime API, not eight.
