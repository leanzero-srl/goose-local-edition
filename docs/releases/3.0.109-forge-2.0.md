# 3.0.109 — Forge 2.0 (Scope Ledger 2)

## What happened
Forge 1.0 stopped separating the strongest models: its top five sit between 0.945 and 0.977, and a review on
9 October 2026 found scoring faults that make some published scores wrong (evals/swarm-bench/forge/DESIGN.md
§17.8). Forge 1.0 is frozen on leanzero.net; its scores stay as published.

## What is new
The Benchmark view's Forge family now runs **Forge 2.0**. One model, in goose, upgrades a working Forge app
(Scope Ledger, the Forge 1.0 reference) to Scope Ledger 2 inside a budget of 300 model calls:

- a live migration of the stored ledger while events keep flowing;
- Tier 1 rate limits: a points quota per virtual hour shared with the people using the site, burst buckets,
  per-issue write limits, and a quota outage the app has to sit out;
- Forge's invocation time limits, concurrent consumer deliveries and eventually consistent storage queries;
- changes to the Jira site mid-run (a sprint closes, a board switches its estimation field, an issue is deleted,
  a permission is revoked);
- an admin panel in UI Kit with server-side permission checks, a signed web trigger for CI, a custom field,
  hardened Forge LLM use, and a boot budget for the two Custom UI surfaces.

The score is `tests earned × critical defects × reliability`, then the caps. Reliability is new: each of the 18
groups of tests multiplies the score by `1 − 0.10 × the shortfall of its worst test`, so a group whose worst
test fails completely costs 10% of the whole score. The task text states the rule. A run is scored on three
seeded scoring sites and each test keeps its worst result.

Every result carries its pictures (the dashboard widget and the sprint action in light and dark, and the admin
panel drawn by the benchmark from the app's component tree) and one graded browser recording.

## How it was checked
The reference app scores 1.0000 on the five calibration seeds and on the three-site reference gate; the starter
scores 0.13; deliberately broken apps lose the tests they should. Every point two trial runs lost was audited
against the task text by an independent reader and a refuter; the five unfair items found were fixed before the
scorer was frozen.

## What does not change
Gauntlet 7.1 / 7.2 and the frozen Forge 1.0 are untouched: their scorers, probes, specs, fixtures and thresholds
are byte-identical, and their call budget stays 150. Their release manifests are refrozen only for the shared
harness files that gained the Forge 2.0 tier (bench_budget.py, isolated_tiers.py, run_build.py,
release_manifest.py). Forge 1.0 sessions stay readable as history; new Forge runs are Forge 2.0.
