# 3.0.98 Gauntlet scores two more app defects instead of refusing them

**A build that leaves out the 3D debug surface, or covers its own 3D view, now gets a low score instead of "Scoring did not finish".**

- **What happened:** Qwen3.8-27B's Gauntlet 7.2 build could not be scored on 2026-10-05. Its 3D view drew in WebGL2 but never exposed `vs7dbg`, the debug surface the task requires, so the scorer could not stage the stream test on a chosen record. Its label layer also sat on top of the canvas and caught every drag, so the camera-coast test never reached the 3D view. The scorer treated both as its own failure and refused the build.
- **Missing debug surface:** when `vs7dbg` is absent on every check the scorer makes, the vendor still sends the stream change and the rows that needed the debug surface score zero. Each one says why.
- **Covered canvas:** when the app's own element sits over the canvas at every point the scorer aims at, the two camera-coast rows score zero and name the element. A user cannot orbit that view either.
- **Still refused:** any other unclear case, such as a debug surface seen even once or an aim that missed for another reason, still refuses, so a fault in the scorer itself never becomes a low score.
- **Nothing else changes:** the benchmark task, the vendor service and every other check are the same. Gauntlet 7.1 keeps its frozen behaviour.

**Retry scoring a refused build:** open the run in the Benchmark view and choose "Retry scoring". It re-grades the saved build with this version's scorer, without new model calls.
