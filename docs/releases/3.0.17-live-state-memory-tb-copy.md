# 3.0.17 Live engine state, honest memory, and model copy over Thunderbolt

The LeanZero MLX tile goes slate at rest and shows what the engine is doing — prefill in blue, writing in green, with prompt and generation rates, counters and who it is serving (`GET /mlx-engine/serving`). A menu-bar tray carries the same live state.

Available memory on macOS is now measured the way the OS reclaims it: (free − speculative) + file-backed + purgeable from host_statistics64. The old sysinfo reading left out the file cache and subtracted the compressor twice, so the page read 0.0 GB free on a 128 GB Mac that memory_pressure put at 88% free, and the mount gate could refuse a model that fit. The recorded case now reads 59.3 GB available (24.6 GB reclaimable cache) and the 27B mount is allowed. The page and tile say "available" and name the reclaimable part.

A downloaded model can be pushed to a linked Mac instead of downloaded again: Thunderbolt is detected by hardware port and negotiated speed, the copy is per-file sha256-verified with resume, and the same offer appears when a download finishes. Measured between an M4 Max and an M3 Ultra: 2.04 GB/s verified over Thunderbolt 5 versus 0.093 GB/s over Wi-Fi.

LeanZero Link peers are now dialled through tailscaled's loopback SOCKS5 listener. Under userspace networking the host had no route to mesh IPs, so every peer call from goose failed; a missing proxy is now a named error rather than a direct dial.
