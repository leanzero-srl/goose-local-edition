# 3.0.123 — no local model restore at launch unless you turn it on

## What happened

At every app start the tray read "Restore failed — Could not restore NVIDIA-Nemotron-3.5-Bolt-74B-A9B-MLX-4bit on this
Mac". On launch goose re-started the local model that was last started and not stopped, and that record named a model
that had since been deleted. The owner does not want a restore at launch.

## The change

- New setting, Settings › App › "Local model at launch" (config.yaml `GOOSE_MLX_RESTORE_AT_LAUNCH`), OFF by default.
  Off: goose restores nothing at launch and shows no "Restoring…" or "Restore failed" anywhere. The record of what was
  last started is still kept, so turning the switch on later works. A malformed engine setting can no longer turn the
  launch into a failure while the switch is off.
- On: a record whose model folder is provably gone is forgotten quietly, with one log line. "Provably" means the models
  folder lists at least one real model (a folder holding only `.DS_Store` or lock files proves nothing, which is what an
  unplugged network share looks like), and the forget runs only for the launch restore, never for a model the engine is
  serving. A model that is present but fails to start still reports the failure as before.
- Deleting a model in Providers › Models clears a restore record that names it (this Mac's single or split record, and
  the record for a linked Mac's copy).
