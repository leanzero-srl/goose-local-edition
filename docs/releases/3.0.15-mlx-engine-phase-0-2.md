# 3.0.15 MLX engine: thinking controls per model, telemetry off, an honest live rate, a measured bench

- Thinking controls (d276b685b, febce6902, 5b977f8e9): the sidecar reads each model's chat template into a capability record (thinking switch, the template's own effort levels and default, preserve-thinking, budget-forcible) and Providers › LeanZero MLX › Sampling shows only what the template declares — Thinking Auto / On / Off and Effort at the model's levels (Qwen3.8-27B: xhigh / medium / low). Defaults send byte-identical requests to today (proved by test); non-default choices go to the MLX engine only, as chat_template_kwargs, captured per session. Under Auto the engine still turns thinking off when tools are sent.
- Telemetry (927d2ded5): the engine is spawned with DO_NOT_TRACK=1 and RAPID_MLX_TELEMETRY=0.
- Live tile (61045680d): the tokens/sec readout is computed from requests that wrote ≥2 tokens and the idle "last run" is the last rate the view measured — rapid-mlx's aggregate reads 1,048,576 tok/s after a one-token request and is never shown.
- MLX engine bench (703eaf080, evals/mlx-engine-bench): three fixed workloads on the engine directly; baseline for v0.14.3-lz.1 recorded (short chat TTFT 1.19 s / 22.1 tok/s; 32k prompt TTFT 184.9 s; goose tool loop turns 2–4 TTFT 27–35 s re-prefilling 3.6–4.2k tokens). MTP depth A/B kept K=3; the cache-persistence change measured worse and was not shipped.
- The transient-tail cache marker (50b02e9b8) ships inert: sent only to an engine that declares it; the engine pin stays on v0.14.3-lz.1 (lz.2 measured 29–38% faster tool turns but changed 2/12 greedy answers — pending the owner's call).
