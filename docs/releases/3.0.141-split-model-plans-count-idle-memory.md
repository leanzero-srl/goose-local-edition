# 3.0.141 — a split model plans with the memory macOS can actually give it

Everything merged since 3.0.140 (`git log v3.0.140..v3.0.141`).

## Split models (two Macs)

- **The split planner now counts inactive memory as available, the same way the running split already did.** On
  the workhorse with nothing loaded, macOS showed 66.6 GB free plus 12.2 GB of inactive memory and no memory
  pressure, but the planner only counted free memory plus file cache (about 70 GiB). MiMo at 262k context needs
  about 76 GiB on that Mac for layers 18/30, so the planner offered 17/31 instead, which puts the other Mac over its
  GPU memory limit, and the model could not start. The planner, the memory hold while serving and the single-model
  memory check now all use one figure: free memory plus file cache, or free memory plus inactive memory when that
  is larger. The safety margin is unchanged: every plan still keeps its reserve (5% of the Mac's memory at least) on
  top, and a Mac whose kernel reports critical memory pressure is still refused.
