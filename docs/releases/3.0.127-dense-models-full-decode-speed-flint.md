# 3.0.127 — dense local models keep their full decode speed; Recursive Flint runs locally

## What happened

- **Dense local models slowed to a crawl mid-run.** On the laptop, a dense 27B model (sabi-noema 4-bit) decoded at about
  4 tokens/s at 47k context while the prefix cache hit every turn, and a Qwen3.8-27B 4-bit fell to 2.9 tokens/s at 170k.
  A short prompt still ran at 15-17 tokens/s.
- **The cause was a dtype promotion in the engine, not the model.** When goose's second request arrived while the
  first was still reading its prompt, mlx-lm padded the new row's empty KV with a float32 array. That turned the whole
  batch's KV cache, and every prefix entry stored from it, into float32: twice the bytes read per token, for the rest
  of the session. The engine log shows it as `kv` per token doubling from 65,536 to 131,072 bytes. goose had already
  fixed the same defect on the two-Mac split (Q-447); the single engine never got it.
- **Recursive Flint** (RecursiveSI/flint, a 39.8B / 2.5B-active MoE) could not load: stock mlx-lm has no `flint`
  model.

## The change

- **The engine is now Rapid-MLX v0.14.3-lz.14** (lz.13 plus the two fixes below). Existing installs that follow the
  default engine move to it on their own.
- **A cold request joining a running batch keeps the model's dtype.** The empty side is padded in the batch's own
  dtype. A float32 prefix entry left by an older engine is dropped once and the prompt re-read.
  `/v1/status` now reports `kv_dtype` (`cold_rows_padded`, `mixed_dtype_extends`, `promoted_entries_dropped`).
- **Recursive Flint is served**: the model, its INT4 loader, its own tool-call and reasoning parsers (picked
  automatically for a local `flint` folder), no default tool-use system suffix and no graded reasoning cap for it
  (Flint has no effort control).

## Verified

- **Live on the laptop, through the app** (sabi-noema 4-bit, Forge 2.0, call 19 at 48k): 65,535 bytes/token stored,
  `cold_rows_padded` 16, `mixed_dtype_extends` 0, decode 15.3 tokens/s (about 4 before).
- **The released tag on the workhorse** (installed with uvx from the tag, the app's engine arguments): a 4.5k request
  joined a 20.9k prompt mid-read; KV stayed bfloat16 (65,535 bytes/token), the follow-up turn hit 20,864 cached tokens.
  Flint boots with its own parsers; text and tool calls parse.
- **Engine suite** (835 test files, CPU) against lz.13: no new failure. The pipeline split's review of the new
  commits: all 7 are not on its code path.
- **Gate:** cargo fmt, clippy `-D warnings` and `cargo test -p goose-sidecar` (443 + integration tests) pass.
