# 3.0.22 Flash across two Macs from the app, Link finds your Macs, the app can reach them

Qwen3.8-Flash-Next (qwen4_exp, 125B MoE, ~98 GB at 4-bit) now starts from Providers › LeanZero MLX › Engine › Distributed as a pipeline split across two Macs, served by the fork's own OpenAI server (pinned fork build): streaming and non-streaming, reasoning split from content, tools through rapid-mlx's own parsers, a 404 for any other model id, cancellation on disconnect. Its KV cache is budgeted per concurrent request — a request is admitted only when its KV fits every rank's budget, otherwise it waits (shown as slots and a queue). Measured on an M4 Max + M3 Ultra over JACCL: ready in ~20 s at a 62,976-token context, 21.7 tok/s streamed; the split's greedy output matched a layer-streamed single-process run of the full model on 640 of 640 tokens. An idle worker rank no longer spins a CPU core (60 → 0 CPU-seconds per idle minute).

LeanZero Link is now the discovery and control plane for the distributed engine: Set up lists your Macs signed into Link first, with memory, the Thunderbolt 5 path and models, and each peer's own goose starts and stops its rank (opt-in per Mac: "Allow this Mac to serve as a distributed node"). The peer shows "Rank 1 of <host>'s distributed engine" while it serves. The ssh path stays for headless Macs.

The app's bundle id is now net.leanzero.goose-swarm. On macOS 26.7 the Local Network privacy alert never appeared for the old id — the app could not reach a peer over Thunderbolt and never showed up in Settings to be allowed — and it did for the new one. Installs of 3.0.20 and earlier cannot auto-update across the change; install this one by hand once.
