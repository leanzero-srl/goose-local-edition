# 3.0.20 Distributed setup detects itself; the app may reach your other Macs

Distributed Set up now asks for one thing — the other Mac's ssh alias — and Detect fills every field from evidence in under two seconds: the Thunderbolt interface, address, netmask and network service, the RDMA device and its IPv4-mapped GID entry, the backend (JACCL when both ends have RDMA on the shared link, with the reason), the models present on every node, free ports, memory and uv. Save provisions a goose-owned Python (mlx 0.32.2, mlx-lm 0.31.3) on each node; a manual Python stays under Advanced. Measured in the installed app: Detect 1.7 s, Save and provision 3.9 s, preflight pass, Start to Ready 10 s, Stop verified on both Macs in 1 s.

Chat reaches the distributed engine: both engines now serve the model under the same derived id, so the swarm router accepts it, and every window finds a run another window supervises (read-only there). The composer no longer offers Mount while the distributed engine owns the Mac.

macOS Local Network privacy: the app's executables now carry their own Mach-O UUIDs (they shared stock Electron's, which TN3179 says makes local network privacy misbehave), the Info.plist explains the use, and the app raises the system alert when it first needs the network. When access is refused, preflight names it (`localNetworkPermission`) with a button to Privacy & Security, a dying local rank says so instead of restarting, and a Thunderbolt copy's failure carries the same flag. Allow Goose Swarm once in the alert, or under System Settings › Privacy & Security › Local Network.

The node card's planned memory is the preflight's with-overhead figure.
