# 3.0.87 SB7.2, and benchmark runs that cost what they should

The Benchmark view now runs **SB7.2**. It's the same Meridian payments task as SB7.1, scored so that the 3D work counts.

**Scoring changes:**

- Structure, overview legibility and event animation now earn points. 3D work is 46% of the weighted checks, up from about 22%.
- The 0.599, 0.699 and 0.799 caps now depend on 3D work only. The 0.899 cap adds event animation and full backend recovery. Text contrast earns or loses UI points and no longer caps the score.
- The default view must be readable, and the published contract gives the numbers:
  - the field spans at least 60% of the canvas width and 60% of its height;
  - the towers are lit at least 2:1 against the background;
  - a viewer can read payment status from the cap colours.
- Every excellence rung is published; none are hidden. The public contract is about 6% smaller than SB7.1's.
- The reference app scores 1.000 under the new scorer.
- SB7.1 results stay readable in your history.

**Cloud benchmark runs:**

- **Real model limits.**
  - OpenRouter and Google runs take the model's context window from the provider's own metadata. Before, goose fell back to a 128k window on models it didn't know.
  - Bedrock runs need the limits set explicitly (`BENCH_CONTEXT_LIMIT`, `BENCH_MAX_TOKENS`) and are refused without them.
  - Bedrock no longer counts cache tokens twice.
  - On new frontier models these defects cut file writes short and compacted the context over and over. Fable 5.1 scored 0.005, and a GPT-6 Astra run wrote nothing in two hours.
- **Prompt caching in long tool loops.** Verified through OpenRouter: on a test session the share of input read from cache went from 0% to 62–82%. The same cache rule now applies to LiteLLM, Databricks and Claude on Bedrock, where it's on by default.
- **OpenAI models now cache in tool loops.**
  - **The problem:** goose rewrote the end of every request: the time, the working folder and the context-usage line. In a tool loop that meant GPT-6 models through OpenRouter never read the prompt cache. Measured on a GPT-6 Luna benchmark run, 0 of 20.5M input tokens came from cache.
  - **The fix:** a chat now keeps these context lines in its history, and adds a new one only when something in it actually changes. Each request then extends the previous one.
  - **Result:** on GPT-6 Luna, every call after the first reads the previous request from cache. DeepSeek and Claude are unchanged.
- **A dropped connection no longer ends a run on the first failure.** goose resends a call that fails mid-answer, up to the provider's retry limit, and tells you it did.
- **The score in the app is the real score.**
  - Grading now uses a fresh vendor, not the one the model built against.
  - Processes the model leaves running are stopped, one by one, before grading.
  - The harness's own log and billing records sit where the model's cleanup can't delete them.
  - An app with no 3D scene gets a low score instead of a refusal.
  - A model whose 3D picking is broken, shown on the page itself, gets scored instead of refused.
  - On the measured run, the score in the app and a clean rescore agreed within timing noise (0.4993 vs 0.5051).
- **The run shows what it actually cost.** On OpenRouter, the bill comes from OpenRouter's own generation records and reads like "Billed $0.62 (OpenRouter, 140 requests)". goose's token-price estimate is no longer shown as the bill. Google and Bedrock show "Billing not available", because neither provider exposes a bill per call.

**Measured cost.** SB7.1 builds by DeepSeek v4.1 Flash were billed $0.33–$0.62 each. Repriced at list prices, those same trajectories come to $24–$53 for GPT-6 Astra and $15–$27 for Fable 5.1. These are estimates, not invoices.

**Also in this release:** the local-engine and LeanZero Link work tested as builds 3.0.40–3.0.86, and a session header in the Benchmark view that no longer squeezes its title into a narrow column.

**Known issues:**
- One run per model is a noisy sample. The same model on the same host scored 0.799 once and 0.505 the next time.
- On OpenRouter, an open-weight model is served by many hosts of different quality. For a comparable score, pin a host. In the OpenRouter settings, under more options, set `OPENROUTER_PARAMETERS` to, for example, `{"provider":{"order":["deepseek"],"ignore":["relace"]}}`.
