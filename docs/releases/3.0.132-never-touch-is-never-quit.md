# 3.0.132 — never-touch and protected apps can never be quit

A fix release on top of 3.0.131. In 3.0.131 the Free up memory dialog could show an app from your never-touch list
(Outlook on one test Mac) as "Protected" and still offer a Quit button next to it. Nothing in the live test pressed
it, but the button should never have been there and the engine behind it did not refuse either. 3.0.132 closes it
at every layer, and fixes two smaller things the 3.0.131 live test found in jobs on My Macs.

## Never-touch and protected apps are untouchable

- **One rule decides.** An app or process is untouchable when it matches your never-touch list (by bundle id, by
  name, or by a fragment, so "Outlook" covers "Microsoft Outlook") or when goose protects it (a system process, a
  launchd job, an MCP server, an engine goose did not start). Every path that can quit, force stop or unload
  something checks that rule first.
- **No Quit, Unload or Force stop button on those rows.** The row shows why it is protected instead, and
  the engine no longer counts them as memory goose can free.
- **The engine refuses too, not just the dialog.** A request to free memory, from this Mac or relayed over Link
  from another one, is refused for an untouchable item with a reason code (`neverTouch` or `protected`), and the
  check is repeated right before each step runs, on a fresh look at what is running.
- **Stopping another MLX engine checks protection.** The "stop the other engine" action now refuses a process that
  is protected, run by launchd, or on the never-touch list, before it sends any signal.

## Jobs on My Macs

- **"Can take ~N more" counts heavy slots.** A Mac card said "2/7 heavy ... can take ~7 more" when memory had room
  for 7 but only 5 heavy slots were free. For a heavy job the number is now the smaller of what memory allows and
  the free heavy slots, so that card reads "can take ~5 more". Light jobs are still counted by memory alone.
  Placement ranks on the same number, so a Mac with lots of memory but few free slots no longer looks roomier than
  it is. (D15)
- **The placement order is described as it works.** The API description said a Mac with someone at the keyboard is
  a last resort. It never was: placement goes this Mac first (or last, under Other Macs first), then the most room,
  and someone at the keyboard only breaks a tie between Macs with equal room. The description now says that. (D16)

## Upgrading

Install over 3.0.131. Your never-touch list, protection settings and the "Where my jobs run" setting carry over
unchanged.
