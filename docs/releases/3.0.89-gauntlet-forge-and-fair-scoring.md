# 3.0.89 Gauntlet and Forge, and fairer scoring

**Two benchmark families.** The Benchmark view opens with a large **Gauntlet | Forge** switch.

- **Gauntlet** is the new name for the SB payments benchmark. Gauntlet 7.2 is the current version. Internal ids are unchanged, so earlier results and history stay as they are.
- **Forge** is a new benchmark: one model builds a working Atlassian Forge app for Jira, graded offline by running it. Forge 1.0 is in preparation: you can prepare its kit from the app now, and Forge runs open once leanzero.net opens the Forge board.

**Publishing.**

- Any finished run on the current benchmark can be published, not only the latest one. Each run keeps its own result.
- A Gauntlet run whose app never served a page can now be published. It shows "No recording: the app never served a page" instead of a video.
- Earlier runs that leanzero.net lists as baselines now show their "Live on leanzero.net" link.
- Clicking a run in the history opens it straight away.
- Breakdown details that used to read "[object Object]" now show their values.

**Fairer Gauntlet scoring.** More of what the app a model builds gets wrong is now scored instead of refused:

- If the app rejects every webhook delivery in the load test, the latency-under-load checks score 0.
- If the app never loads the payment the scorer picks for the stream test, the run is now scored: that payment's part of the decisions check, and the stream-apply checks it could not time, score 0.

**Models that only read text.** On OpenRouter, goose no longer sends an image to a model that only accepts text. It sends a short note saying the image was left out, so the run continues. Before, such a run ended with an error.
