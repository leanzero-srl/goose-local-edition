# 3.0.120 — model delete follows the SSD links

## What happened

Providers > Models refused to delete a model on the Mac Studio with "refusing to delete … resolves outside
~/.goose/models". On that Mac the publisher folders under `~/.goose/models` are links to an external SSD. The
model list follows those links, but delete refused anything that resolved outside `~/.goose/models`, so the list
showed models that the delete button could not remove.

## The fixes

- Delete follows the same links the model list follows: a linked publisher folder, or a per-model link (the link
  is removed after its target). It still refuses anything that is not a model folder (no `config.json`), and it
  never follows a link to the models folder itself or to any folder above it (checked by path and by device and
  inode, so the macOS Data-volume firmlink cannot hide it).
- A cancelled download or copy never deletes a model folder it did not create. Before, cancelling a "Resume" of an
  incomplete model you already had could remove the whole folder. On a disk with no backup that was the only copy.
  It now removes only the unfinished `.part` files of a folder it did not create.
- When a Mac sees the models folder through a read-only share, a delete there says so and names the fix: delete
  it on the Mac that owns the disk.
