# 3.0.9 Providers with a chosen default, projects by directory, our own context menus

Nine commits on top of 3.0.8 (cf4737b73 … 863417d61), all sidebar and provider surface; no swarm engine file touched.

- Cloud Providers: no hard-coded connection-test model. Key → the provider's own model list → a chosen DEFAULT that leads node selection (`provider_default_models`; `Verification { Proven, ListedOnly }` — a public listing never proves a key). Real provider marks on the tiles. `swarm_inventory().with_configured(|| true)` so onboarding's Goose Swarm works on a fresh install; the configure error is shown instead of swallowed.
- Projects derived from each session's working directory (`deriveProjects`), no Unfiled; sidebar resizes by dragging its edge (`navigation_width`).
- Agent Work and Benchmark trees shaped like Projects (`tree.tsx` register); benchmark type is a dropdown; the run view is URL-driven.
- Our own `TreeContextMenu` on sessions, skills, memories, desks, runs and MCPs; "Start an AI session about this" always loads developer + memory + skills + extensionmanager (`WORK_ON_ITEM_EXTENSIONS`) and its prompt names where the item lives, the tool that writes it and how to fork it.
