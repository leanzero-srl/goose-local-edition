# 3.0.11 The UX audit pass: honest readiness, findable sessions, memories you can see into

A live audit of 3.0.10 (Playwright over CDP against the installed app, every view screenshotted; findings and harness in `~/goose-builds/ux-audit/`) plus a survey of common agent-app complaints. Fixes, by surface:

- Chat: the composer no longer shows a green dot when nothing can answer; a solid "No model is mounted — <node>" strip with Mount / Open Providers appears when engine facts prove no node can serve. A failed turn is now persisted (user-visible, hidden from the model), so reopening a session shows the failure. Ask-AI sessions are named after their item ("Memory · …", "Skill · …") and a long seeded brief collapses. Real placeholder; no success toast on every open; one timestamp format; the empty cost chip and "$0.0000" on local models are gone; "Set up agent" says what it is.
- Skills and Memories: one library shell — full-ink title, a real search field (⌘F focuses it), 2-line previews (a `display` class was defeating line-clamp; the build now refuses the pairing), the first item open instead of an empty pane. Memories show scope, source, category, tags, file and time, the originating session for memories saved from a proposal, markdown rendering, and inline Edit / Delete.
- Home and sidebar: "Pick up where you left off" (recent sessions, desks waiting on you, New session in the last project) instead of "Start from a project"; a filter over projects and sessions; Projects, Agent Work and Benchmark each fold to their header (remembered per section).
- Providers: the MLX page leads with a status card and the state's action (Mount / Unmount / Retry); engine details fold away when stopped.
- New agent: our own checkboxes with tool names and descriptions, cadence presets, a searchable timezone list, a real title.
- MCPs, Benchmark, Agent Work: consistent buttons and section headers; the sidebar "+" opens a focused New run card; an old failed run is a chip, not a red banner; phase blocks coloured by who did the work; lane cards no longer repeat the result.
- One rule per fact: `deviceEnabled()` and a single local-provider list.
