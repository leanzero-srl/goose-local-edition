# 3.0.93 Gauntlet scores a slow 3D view instead of refusing it

**A build whose 3D view is too slow now gets a low score, not "Scoring did not finish".**

- **What happened:** the Gauntlet 7.2 scorer gives its 3D-view probe 480 seconds. When an app's scene was still busy at that limit, the scorer refused to score the whole build, and the result could not be published. GLM-5.3's build was refused this way on 2026-10-04.
- **The fix:** the visual checks the probe could not reach now score zero, and every other check is graded as usual. Each zeroed check says why: the 3D view did not finish within the 480-second budget.
- **The machine's load is recorded:** the scorer notes the computer's load when the 3D probe starts and ends, and shows it with the result. It is information only and does not change the score.
- **Nothing else changes:** the benchmark task, the vendor service and every other check are the same. Gauntlet 7.1 keeps its frozen behaviour.

**Retry scoring a refused build:** open the run in the Benchmark view and choose "Retry scoring". It re-grades the saved build with this version's scorer, without new model calls.
