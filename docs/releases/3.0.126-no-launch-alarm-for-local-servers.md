# 3.0.126 — no launch alarm for a local server that isn't started; CI green again

## What happened

- **The launch alarm.** Every launch, on every Mac, showed "Provider connections need attention — OpenAI: OpenAI could
  not list models: Network error: Could not connect to 127.0.0.1:8090". OPENAI_HOST points at goose's own local MLX
  engine on purpose (local benchmark runs reach it through the OpenAI provider). The engine only listens while a
  local model is loaded. The launch check, built to prove saved cloud API keys, treated the stopped engine as a
  broken connection.
- **The CI pipeline** was red on main for days. Four separate causes:
  - A Windows-only compile error (fixed in d40be008a).
  - A test that read other tests' telemetry lines.
  - Sidecar tests that used port 8090, where a real engine may be running.
  - A real shell bug: a killed command whose output pipe was still held by another process stayed a zombie, so its
    group looked alive.
  - Desktop tests that the runner, which gives way to video work, slowed down 25-38x in bursts.

## The change

- **The launch and recheck connection check now asks each provider for its real endpoint.** A loopback endpoint
  (127.0.0.0/8, ::1, localhost, 0.0.0.0, any port) whose TCP connect is refused is recorded as a state,
  "local server not running", not an error.
  - The launch toast skips it.
  - Every provider surface shows a "Not running" chip and "Nothing is running at <address> yet": the Cloud Providers
    tab, the Provider Configuration grid, node cards, New node and the Benchmark entrant.
  - The probe gives up after 3 s, so a dropped connect never holds the check lock for the OS's 75 s retry.
- **Every other alarm stays.** A cloud key the provider rejects and a remote endpoint that is down still alarm at
  launch. Saving a provider still proves the connection, exactly as before.
- **The toast shows one line per provider** instead of one run-on paragraph.
- **Shell:** a detached command's leader is reaped as soon as it dies.
- **Tests and CI:**
  - The telemetry test reads only its own lines.
  - Sidecar test managers never use the owner's engine port.
  - Two race fixes.
  - jsdom 29 halves the heaviest view tests.
  - On the CI runner a desktop test may take 60 s; locally the limit stays 5 s.

## Verified

- **Packaged app with a release engine:** the launch toast showed only a revoked cloud key, and the OpenAI tile read
  "Not running".
- **Tests that fail on the code before this change:** loopback refused → state, not error; a remote host still
  errors; a stopped endpoint is still refused on save; the 3 s connect bound; the not-running card; the launch toast
  for the old vs new engine answer; the zombie reap (20/20 after); the telemetry isolation (0/25 failures after,
  7/25 before).
- **Two independent reviews**, of the alert fix and of the CI fixes. Every confirmed item was fixed before release.
- **Gate:** fmt and clippy `-D warnings` pass. cargo test goose: 2,334 and every integration binary pass, plus the
  known environment failure `test_codex_provider` (it needs this Mac's Codex login). goose-cli, provider crates,
  swarm and sidecar pass; one sidecar test that reads the owner's real 27B checkpoint off the network-mounted SSD
  failed once and passed on rerun (it skips on CI). Desktop: lint, i18n (15 locales), and vitest 5,066 passed.
