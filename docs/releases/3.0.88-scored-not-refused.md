# 3.0.88 Benchmark runs are scored, not refused, when the app is at fault

When the app a model builds is broken in certain ways, the SB7.1 and SB7.2 scorers used to refuse the whole run. Now they score the run and charge the defect. These cases are now charged:

- The app's service never binds its port, so the later phases never run.
- After a crash restart, the app's sync stops before the restart test can fire.
- The app never sends the request the cache test needs.
- During the network partition, no status read returns JSON.
- A draft can't be created, or is gone after a restart.
- The notifications endpoint never returns its list.
- Every API latency request fails with an HTTP error.
- The summary endpoint never answers during the concurrency test.
- The app pays the same draft twice.

A run is still refused when the fault is the harness's: the browser probe crashing or timing out, missing fixtures, or too little overlap on a loaded machine.

If a run failed to score on 3.0.87, open it in the Benchmark view and use Retry scoring.

The reference app still scores 1.000, and an untouched starter still scores low.
