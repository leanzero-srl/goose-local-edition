# 3.0.131 — jobs on measured load, and a memory clean that only touches what goose owns

3.0.131 carries everything that was planned for 3.0.130, plus two changes on top. **3.0.130 was never published.**
Its tag exists, but a review before release found that its one-click "free goose's own memory" could stop an MLX
engine goose had not started (on one test Mac, a 29.7 GB rapid-mlx server started by hand) and run
`lms unload --all` under LM Studio users. That build was held back. 3.0.131 ships the safe clean described below
in its place.

## From 3.0.130 (first published here)

- **Choose where your jobs run.** Settings for jobs on My Macs has "Where my jobs run": My Mac first (the default,
  `local-first`) runs a job on this Mac when it has room, else on the other Mac with the most room; Other Macs first
  (`selfish`) sends it to the other Mac with the most room first and keeps this Mac free. The setting saves at once
  and sits in `~/.leanzero/node-limits.json` as `"strategy"`; the `LEANZERO_LINK_JOBS_STRATEGY` environment variable
  overrides it. The Run a job dialog can override it for one job when Best Mac is chosen.
- **Jobs wait in line instead of failing.** When no Mac has room, a job sent to Best Mac waits in a first-in,
  first-out queue on the Mac that sent it and starts on the first Mac that has room. The job row says "Waiting, #n in
  line", the job's dialog shows why each Mac said no and, once placed, "Placed on X". A waiting job can be cancelled
  (with a confirmation) before it ever starts.
- **Free up memory.** Each Mac card and the per-Mac load panel have a Free up memory entry. It lists what holds
  memory, says whether a model would fit after freeing, and frees what you choose. What was freed is measured per
  process until the numbers settle, not estimated. It works on another Mac over Link too. What it may touch changed
  for this release; see "A memory clean that only touches what goose owns" below.
- **Run a job lists every online Mac.** A Mac whose jobs switch is off is still listed in "Run on", disabled with
  "jobs are off on this Mac", instead of silently missing. Best Mac stays first. (D11)
- **The Run on field shows names.** It showed the raw value `__best__`; picking from any list field now shows the
  option's label. (D12)
- **A Mac that drops off shows Offline within 3 seconds.** Link checks each peer every 500 ms with a 900 ms bound
  and the My Macs roster refreshes every 500 ms, so a Mac that disconnects reads Offline in under 3 s (it took 3.4
  to 4 s before). (D2)
- **A prompt job whose turn failed is Failed.** When the model turn fails (for example "no node can serve this
  turn"), the job now ends Failed with exit 1 and the reason, instead of Done with exit 0. A cancelled prompt job
  ends Cancelled (143). (D13)
- **Deleted jobs leave the list at once.** A finished job whose folder under `~/.leanzero/jobs` was deleted no
  longer stays listed until goose restarts. A running job stays listed, since it still owns its process. (D14)
- **The app's own benchmark runner is recognised.** A Mac running the packaged benchmark
  (`.../swarm-bench/bench/run_build.py`) is seen as busy with a benchmark from its command line, without waiting
  for the run-file check. A prompt that only mentions the file is still not counted. (D5)
- **Mac cards never show old numbers silently.** While the window is hidden the cards keep reading slowly (every
  15 s) and read at once when it shows again; a card whose facts are older than 10 s says "updated Xs ago" until a
  fresh read arrives.

## New in 3.0.131

### Jobs are admitted on measured load

- **Busy means measured, not flagged.** A Mac refuses a job only for a measured reason: the job's memory need would
  push free memory under the floor, every heavy slot is taken, load per core is past the backstop (2.0 by default),
  thermal pressure, a running benchmark, or a physical state that would kill the job (lid closed and asleep, a heavy
  job on battery). Every refusal and every verdict carries its numbers, for example `busy: memory 12% free < 20%
  floor`.
- **Several heavy jobs per Mac.** Heavy admission uses slots over the same lock files as heavy-run and node-run
  (slot 0 is `~/.cache/heavy-run.lock`, slot i is `.i`), so goose jobs, heavy-run and node-run share one count.
  The default is `max(2, cores / 4)`, set with `"max_heavy"` in `~/.leanzero/node-limits.json`. One held slot of
  several no longer makes a Mac busy.
- **Someone at the keyboard is a tiebreak, not a refusal.** A Mac in use still takes jobs; it only moves behind an
  equally able Mac. "While someone uses this Mac" is now Take jobs (the default) or Refuse jobs; the old
  "last resort" value reads as Take jobs. Remote turns (`/v1/swarm/execute`) also refuse on measured load instead of on a live session.
- **"Can take ~N more".** Each Mac card shows its verdict line, for example `ok: 1/3 heavy, 94 GB free, load
  0.28/core, can take ~11 more 8 GB jobs`, and the Run a job dialog shows the verdict for each target. A job that
  names no memory need is counted at `"default_need_gb"` (8 GB).

### A memory clean that only touches what goose owns

- **One click frees only goose's own memory.** The default clean unloads goose's own idle engine and stops proven
  left-over goose servers. Nothing else. It sends SIGTERM and waits; it never force-kills, and an engine that does
  not exit is reported, not forced. A left-over goose server must prove it is goose's (same user, same binary, the
  desktop arguments, parent gone) and still keeps the launchd, terminal and ssh protections.
- **Other servers are offered, never pre-ticked.** Ollama, LM Studio and MLX engines goose did not start are listed
  with an Unload button and a "used by" line (TCP clients of their ports, the process that started them, their
  launchd job). LM Studio counts its LM Link connector and that connector's clients as users, so Macs using its
  models over LM Link are shown. Goose checks "used by" again right before it acts and refuses a server that gained
  a user since you looked.
- **Free everything except protected.** A separate view lists every holder. Protected ones are shown with the
  reason and never offered: launchd jobs, terminal and ssh sessions, MCP servers and any app that hosts one,
  browsers driven over remote debugging, macOS itself, running heavy jobs, and your never-touch list. Only goose's
  own memory is ticked. Apps are asked to quit; an app that does not quit (for example one asking to save) is left
  running and reported, and only a separate Force stop, behind a confirmation that says unsaved work is lost,
  sends it SIGTERM.
- **Never-touch list in Settings › App.** Built-in entries (Teams, Outlook, Slack, Zoom, Terminal, iTerm2 and Warp,
  by bundle id) always apply. Your own entries match a bundle id, an app name or a process name, case-insensitively and by
  "contains", so "Teams" protects Microsoft Teams. Each of your entries says what it matches on this Mac, or that
  it matches no running or installed app and so protects nothing now.
- **On another Mac over Link**, freeing still needs that Mac's model-management permission. Unloading other
  servers, stopping other engines and quitting apps there stays off unless that Mac sets
  `GOOSE_LINK_ALLOW_REMOTE_APP_QUIT`. Your never-touch list travels with the request and is added to that Mac's.

## Verified

- Rust: `cargo fmt --check`, `clippy --all-targets -D warnings` (leanzero-link, goose, goose-server,
  goose-sidecar), `cargo test -p leanzero-link`, goose `acp::server::link` (incl. `link_serve`), `swarm_router` and
  `memfree` tests, goose-server `remote_executor` tests, goose-sidecar `memfree` tests.
- Desktop: `pnpm run lint:check`, `pnpm run typecheck`, the full vitest suite, `pnpm run i18n:check` (16 locales),
  `just check-acp-schema`.
- The safe clean was dry-run on a Mac running a hand-started rapid-mlx engine and LM Studio serving LM Link peers:
  neither was ticked, and LM Studio's "used by" named the LM Link connector.
