# 3.0.108 — a wrong-shaped Forge manifest is charged, not a scorer crash

## What happened
z-ai/glm-5.3-prime's Forge build on 2026-10-07 declared its storage attributes as `sprintId: string` instead of
`sprintId: {type: string}`. The scorer's deploy-readiness check expected a mapping at that level, raised
AttributeError, and the paid run ended with no verdict.

## The fix
Every place the Forge scorer reads the candidate's manifest now checks the shape at each level. A value with the
wrong shape fails the matching deploy rule instead of crashing: M7 names each attribute that is not a `{type: …}`
mapping and each index whose partition or range is not a list. Scalars where the schema wants a mapping (for
`permissions`, `app.runtime`, `app.storage`, `permissions.external.fetch.backend`, `permissions.content`, skill and MCP
tool lists, and the LLM tool definitions the app sends) are read as absent and charged by their rules. The GLM build
now scores (0.4745 on its primary seed when replayed through the CLI scorer as evidence), with M7 failing and
"would not deploy".

## What does not change
The benchmarks, contracts, fixtures, vendors and the score of any build whose manifest has the documented shape
(scorer suite unchanged apart from one new test).
