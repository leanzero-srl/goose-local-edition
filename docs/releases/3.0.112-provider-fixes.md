# 3.0.112 — two provider fixes found on benchmark runs

## What happened
- Qwen3.8 Flash (Alibaba via OpenRouter) ended every long Forge 2.0 run with "Server error: Provider returned error": the host sends a 429 rate limit INSIDE the stream, goose read it as a generic server error and gave up after three resends a few seconds apart.
- Gemini 4 Argon on the direct Google provider was refused on its first parallel tool calls: "Function call is missing a thought_signature in functionCall parts". goose treated the per-turn context text that rides beside tool results as the start of a new user turn and stopped sending the signatures for the calls before it.

## The fix
- An in-stream 429 (or error_type rate_limit_exceeded) is the same rate-limit class as an HTTP 429, and the reply loop waits it out with goose's existing rate-limit wait before spending a resend.
- The Google formatter no longer treats a user message that carries a tool result as a turn boundary, so signed function calls keep their signatures (google, gemini_oauth, gcpvertexai).

## What does not change
Benchmarks, scorers, contracts and call budgets are unchanged.
