# 3.0.7 OpenAI-compatible endpoint, Providers menu, provider cards

goosed exposes `GET /v1/models` and `POST /v1/chat/completions` (`crates/goose-server/src/routes/openai_compat.rs`). A completion is one ephemeral goose session: the OpenAI messages become its conversation (system text through the prompt extension, image parts dropped with a warning, `response_format: json_object` appends a JSON-only instruction), `model` is applied through the same calls `POST /agent/update_provider` makes (`provider/model` split on the first slash; `swarm` and `swarm-build` map to the swarm provider), the turn runs with goose's own MCP tools (a caller's `tools` are accepted and ignored), and the session is deleted afterwards unless `x-goose-keep-session: 1` is sent. Streaming answers `chat.completion.chunk` frames and `data: [DONE]`. Errors use the OpenAI envelope: 401, 400 on a bad body, 404 `model not found`, 500 with goose's error text. The existing `X-Secret-Key` middleware also accepts `Authorization: Bearer <the same secret>` on those two paths only, compared constant-time; no other route changed.

Desktop: the navigation row "Goose Swarm" is now "Providers" (label, i18n descriptor in every locale, the page heading; route id and path unchanged; the product name is untouched elsewhere). The provider cards on that page are two columns of content-sized cards: no fixed height, no inner scroll on the description, the Configure button in the card's footer row.

## Validation before packaging

- `cargo fmt --all -- --check`, `cargo build -p goose-server`, `cargo clippy -p goose-server --all-targets -- -D warnings`: passed (exit 0).
- `cargo test -p goose-server`: 36 lib + 34 bin + 7 integration + 3 tls tests passed. The integration file `tests/openai_compat_router.rs` drives the real router and auth middleware: 401 without the secret, 200 with `X-Secret-Key`, 200 with Bearer, Bearer refused on `/config`, 400 on a bad body, 404 on an unknown model. Unit tests cover the message translation (string and parts content, image drop, json instruction, tool/trailing-assistant drop), the model-id split, the delta accumulator and the provider-error sign-off detection.
- Desktop `pnpm run lint:check` (typecheck, ESLint, i18n extract check, all-locale validation) exit 0; `pnpm run test:run` exit 0: 258 files, 2059 tests passed, one existing skipped.
- Live smoke on `target/debug/goosed agent` (HTTPS, self-signed, `GOOSE_SERVER__SECRET_KEY` set) with LM Studio: `/v1/models` 401 / 200 / 200 (X-Secret-Key, Bearer); `/config` with Bearer 401; bad body 400; unknown model 404; `lmstudio/qwen3.5-9b-atlassian-mlx` answered a `chat.completion` ("A clear daytime sky is blue …", usage 44711/60/44771) and a `stream:true` run produced `chat.completion.chunk` frames ("pong") and `data: [DONE]`; zero sessions named "OpenAI-compatible request" remained.
- Two defects the smoke found were fixed before packaging: streamed deltas were joined with newlines (now glued per message id), and a provider failure the agent phrases as a message was answered 200 + `finish_reason: stop` (now a 500 / error frame). The first model tried, `qwen3.8-27b-mtp`, crashes inside LM Studio's MLX draft-model backend (`Qwen3_5MTPDraftModel has no attribute get_input_embeddings`); that is LM Studio's defect and the smoke moved to a non-MTP model.

## Scope and limits

The smoke proves the surface against one local LM Studio model; `swarm` / `swarm-build` and cloud providers went through the same `update_provider` path but were not exercised live. A completion carries goose's full system prompt and tool catalogue (~44k prompt tokens with the developer extension loaded), which is the cost of "goose's own tools run inside the turn". SB7.1 prompt and scorer are unchanged.
