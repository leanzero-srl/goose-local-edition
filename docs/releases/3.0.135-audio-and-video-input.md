# 3.0.135 — attach audio and video to a chat, and a local model hears and watches it

A feature release on top of 3.0.134. You can now drop or pick an audio or video file in the chat, and a local model
served by goose's own engine that takes audio and images answers from what it hears and sees. It also ships the
compaction rework, the per-model prompt-lookup lever and the engine updates made since 3.0.134.

## Audio and video in the chat

- **Drop or pick audio and video files.** The composer takes audio and video the same way it takes images: drag a
  file onto it or use the attach button. Each file shows as a card with its name, an Audio or Video badge and a play
  button, so you can check it before you send. Files up to 50 MB each.
- **The local model hears and watches them.** goose's engine (Rapid-MLX v0.14.3-lz.19) passes audio to a model's
  own audio encoder and turns a video into still frames (one per second, at most 16) that the model sees in order.
  Measured with mlx-community/gemma-4-e4b-it-8bit: it transcribed a spoken clip word for word and described what
  moves and changes in a short video, including text that appears on screen.
- **A model that cannot take them is told, not crashed.** goose asks the engine which inputs the served model
  takes. When audio or video is not among them, the model gets a short note naming the attached file instead of
  the file. Anthropic, Bedrock, Databricks and Snowflake always get that note; other OpenAI-compatible providers
  (OpenRouter, for example) are sent the audio and video as they are, and whether they accept them depends on the
  provider and model.
- Audio and video are attached in the desktop app only; the goose CLI has no attach path for them.

## Compaction

- **Compaction waits until the window is really nearly full.** With no percentage set, a chat compacts at the
  window minus room for the next answer and one tool result (not before 80%), instead of at a fixed 80%. The context
  meter says "Auto compact near full (not before 80%)" in that case. A set percentage works as before.
- **goose counts the conversation the way the engine does.** The decision to compact now reads the prompt size the
  provider reported for the last call, plus goose's own count of what came after, so a long session with many tool
  calls no longer compacts early.
- **The summary keeps the facts.** Beside the model's summary, goose keeps your messages word for word, every file
  written with what it defines, the errors still open, the commands that worked and the last ten tool calls. A
  summary that is missing its sections is asked for once more, then kept with a flag; goose no longer falls back to
  re-sending the whole transcript to a local model.

## Local engine

- **Prompt lookup per model.** The MLX profile form has a prompt-lookup (n-gram) lever per model, and a choice to
  keep its table on disk. On code edits the measured speed-up was about 3x; it gave nothing on other work.
- **Qwen Flash-Next.** Its built-in MTP head is served, it loads in the oQ4e layout, its images go through the fast
  text lane, YaRN rope scaling can be set in a model profile past 262k tokens, and prompt lookup works under
  sampling.
- **The memory guard reclaims before it refuses** a long turn, and streamed answers keep their whitespace.
- **Every Mac moves to the new engine.** An install that kept the default engine of 3.0.134 or older follows the
  new one on start; an engine command you set yourself is left alone.

## Gauntlet

- **A build whose own service dies on restart is scored, not refused.** In SB7.2, when the candidate's ledger
  service exits by itself (for example a restart that cannot bind its port), the rows that need it score 0 and the
  verdict names the exit, instead of the whole run being refused. Its graded browser recording is published as the
  clip. SB7.1 is unchanged.

## Upgrading

Install over 3.0.134. Your settings carry over. The first start downloads the new engine version once.
