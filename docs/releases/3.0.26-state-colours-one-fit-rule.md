# 3.0.26 A colour per state, one fit rule, a Mount that knows about splits

The engine tile, the node cards, the tray and a linked Mac's own tile now speak one palette: not loaded dark and outlined, idle grey, loading or making room amber with a progress bar, reading a prompt blue, writing green, held orange, failed red. Starting a split shows each Mac loading its part — verified live: "Mihai Macbook · L0–15 · 30.9 of 52.3 GB", "Work's Mac Studio · L16–47 · 24.9 of 43.8 GB", then Ready in ~25 s.

One fit rule decides everywhere (the single-engine mount, the placement card, the tile, the split's preflight and the local harness): budget = min(available − 9.3% of RAM, the Mac's GPU ceiling). A model that only fits across Macs is no longer mounted on one Mac and refused: the tile's button reads "Start across both Macs" and starts the split, and the reason is written under it. One failure shows one banner. A Mac Studio viewing the MacBook over LeanZero Link now badges such a model "Needs both Macs" instead of "Too big".

## Known

While a split serves, the tile shows green with requests in flight but not yet the reading/writing distinction and its rates; and the split engine names Flash with the single engine's model id in /v1/models. Both are being fixed for the next release.
