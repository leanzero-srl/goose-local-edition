# 3.0.6 provider connection validation

The desktop cloud catalog contains the fourteen requested key-based providers. Setup validates authenticated inference through the provider's real adapter before accepting changes. Failed or cancelled checks restore the prior configuration. Each new desktop backend connection rechecks saved providers; failed or unchecked connections are excluded from benchmark and node selection, with errors retained in settings. Recheck connections retries without restarting. Tests send a brief inference request and can incur normal provider charges.

Azure Foundry accepts modern /openai/v1 endpoints without adding legacy deployment paths, and explicit API keys take precedence over old AD tokens. Bedrock bearer setup no longer exports saved AWS values into process environment. Model choices tested during migration/startup are persisted for node setup. The ten newly exposed node adapters offer the setup-tested model; the existing four retain their provider catalog listing.
