# 3.0.140 — a model split across two Macs keeps long chats warm past half the context

Everything merged since 3.0.139 (`git log v3.0.139..v3.0.140`).

## Split models (two Macs)

- **Long chats on a split model no longer re-read the whole conversation every turn.** On a model split across two
  Macs with a tight memory plan (MiMo at 262k context, layers 18/30), the prompt cache was only allowed one live
  row's worth of memory. From about 127k tokens it could no longer keep the chat's previous turn beside the new one,
  and from about 141k every reply started from zero: 10 to 20 minutes of prompt reading per turn, growing with the
  chat. The plan already reserves room for that copy inside the prefill workspace. The cache now uses that room
  while nothing is being read in (the end of a turn, generating, idle), and keeps the strict limit while a prompt is
  read in. In the replay of that run the chat now stays warm every turn up to about 253k tokens, with no change to
  the split and no change to the GPU memory limit.
- **Both Macs need this version.** A Mac on 3.0.139 or older refuses the new split spec with a message that says to
  update it, instead of a parse error.

## Settings

- **goose keeps your own and unknown keys in config.yaml when it writes the file.** A new test pins that every write
  goose makes leaves keys it does not own in place, so a run setting such as a context limit is never wiped by an
  unrelated change.
