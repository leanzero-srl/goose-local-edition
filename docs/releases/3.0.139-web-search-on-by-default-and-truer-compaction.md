# 3.0.139 — web search and documents work out of the box, and compaction summaries you can trust

Everything merged since 3.0.138 (`git log v3.0.138..v3.0.139`).

## Bundled tools

- **LeanZero Web Search and LeanZero Documents are there from the first start.** goose only corrected these two
  bundled tools when config.yaml already listed them, so a fresh install or an upgrade never added them. Every search
  then failed with "Tool 'web-search' not found" and the model answered from memory instead, sometimes wrongly. A
  packaged start now adds both, switched on. If you removed one, it stays removed, and one you switched off stays
  off. Web search needs no key: it falls back to the bundled browser.
- **A missing tool makes the model say it could not do the step.** When a model calls a tool that does not exist,
  the error it gets back now tells it not to answer as if the step had run and to tell you it could not be done.

## Compaction

- **The summary no longer says "Pending Tasks: None" when your last message has no reply.** goose itself now works
  out whether the newest message was answered and writes a "Not answered yet" section, so the next turn picks up
  the open request instead of thinking the work is done. goose's own end-of-turn notices do not count as an answer.
- **No more invented folders in the summary.** A summary that named a path such as `/export/...` that does not exist
  sent the next command to the wrong place. Paths are now rebased on the chat's own folder where that is where the
  file is, and a path that is not on disk is marked as such (never inside a code block).
- **No leaked analysis block.** Scratch sections such as `<analysis>` that the model writes while summarising are
  stripped before the summary is used.
- **Steps that read a here-document no longer settle each other**, and redirecting output (including `>& file`,
  which is a write) no longer stops a look-up from counting as one.
