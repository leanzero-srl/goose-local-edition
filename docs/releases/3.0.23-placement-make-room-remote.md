# 3.0.23 Where to run it, Make room, a model on the other Mac, images for Flash

The Engine tab now answers "where should this model run?". For the chosen model and goal (Chat · Long documents · Many requests) it enumerates what goose can run — this Mac alone, a linked Mac alone, a pipeline or tensor split — drops what doesn't fit, predicts reading and writing speed (a measured number when one exists, otherwise an estimate from each Mac's chip, memory bandwidth and GPU ceiling, shown as a range), and recommends one with the reason every alternative lost. Measure speed runs a fixed ~2k-token prompt and 256 tokens and records the result, which replaces the estimate. The model picker shows a badge per model: fits this Mac, fits a linked Mac, needs both Macs, or too big (short by N GB).

Make room: when a Mac is short on memory, goose asks macOS to reclaim — Apple's memory_pressure raises pressure to WARN, releases at once (and at once on CRITICAL), and waits until available memory stops rising — so idle apps are compressed and caches dropped. Measured +7.7 GB on the MacBook and +3.2 GB on the Mac Studio. It never runs while a model is loaded on that Mac and quits nothing. Distributed budgets are now each Mac's GPU ceiling capped by what is available after reclaiming, less a ~9% margin (was 21% of RAM): 107.5 GB on the M4 Max, 77.8 GB on the M3 Ultra.

A model can run on a linked Mac alone and chat reaches it through an authenticated LeanZero Link proxy (streaming, cancellation, the cut-off rule preserved); opt-in on the serving Mac. Measured: the 27B on the M3 Ultra answered a MacBook chat at 30.1 tok/s.

Flash (qwen4_exp) takes images across the two-Mac split: the vision tower runs on the first Mac and the position table travels with each batch; a real screenshot was read correctly.

KV-cache compression is a per-model setting (off / 8-bit / 4-bit) with its measured trade-off shown; default off (8-bit changed 5 of 13 answers on the 27B, both kept every long-context fact). Engine pin Rapid-MLX v0.14.3-lz.4: a logprobs request no longer kills an MTP engine. A dead engine now reads failed with its reason instead of running. The "Run a prompt on a linked device" card is gone.
