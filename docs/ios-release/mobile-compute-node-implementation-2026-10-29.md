# Mobile compute-node definitions

This implementation closes the missing compute-definition path. The earlier Add a Mac screen only described local Link enrollment and syncing registered hosts; it never created a provider/model definition. Existing mobile provider/download/steering receipts do not prove node creation. Physical host installation and same-account enrollment remain local to that Mac. The original plan's proposed single-use invitation is not implemented by this change.

The owner exposes GET /v1/controller/management/nodes with models.read. Its allowlisted response contains nodes (id, name, kind, nullable model/provider, macs, editable, definition_revision), configured provider/model choices, complete local model IDs, an explicit optional local_models_error, supported_kinds and implemented action capabilities. It never returns the raw nodes config, strategy/chat IDs, provider secrets or diagnostics containing local paths. Unavailable local storage is named and disables only MLX creation; cloud/endpoint definitions remain readable/removable. Capabilities require both the receiving Mac's management switch and the current device's models.manage scope.

Existing durable management commands now support node_create with id/name/kind/model/optional provider, and node_remove with id/expected_definition_revision. The owner fixes new origin=user, keep_loaded=false and no pool identity. Cloud/endpoint definitions name a configured provider and advertised model; an owner-local MLX definition uses a complete installed model and server-created single/local placement. Client-supplied placement, pool ownership, origin, defaults or extra fields are rejected. Creating a definition never loads a model, starts inference, changes chat/default routing or modifies a strategy. Removal checks the exact selected definition fingerprint and preserves the core usage refusals without cascade flags or implicit live-session acknowledgement; pool definitions cannot be remotely removed.

All commands retain account/owner/store-generation/scope checks, the local management gate, immutable command identity and durable acceptance/dispatch/completion receipts. After awaited model/provider/session preparation, authority, store generation and host policy are checked again immediately before the synchronous shared config mutation. Core written=false is rejected, never labeled delivered.

ACP and controller config mutations share an owner-process mutex. NodesConfig carries a default-zero revision; whole-config writes must match the current revision, and successful stores increment it. This covers write, remove-node, chat-node-set and remove-strategy operations, preventing stale desktop saves from dropping newer changes or resurrecting a removed definition. Single-definition create/remove capture fresh state while holding the same mutex. Missing-revision clients cannot bypass a nonzero stored revision. Current desktop raw-ACP config-spread callers preserve the additive revision; generated types/schema must accompany the change. This is same-owner-process coordination, not an interprocess lock against separate goosed processes or external config editors.

Independent design/source review found and repaired two defects before test execution: authority could change while local model listing awaited, and unavailable model storage prevented unrelated cloud inventory reads. Latched revoke/host-toggle tests and an explicit unavailable-storage cloud-remove control cover those paths. Other focused controls cover immutable receipt replay, exact-definition removal, read-only capability suppression, stale desktop writes, concurrent node insertion/chat-set edits, pool/usage refusal, local-only installed MLX shape and rejection of extra configuration fields.
