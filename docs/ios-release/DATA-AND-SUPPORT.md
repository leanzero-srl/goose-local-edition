## Retention and account deletion: what the code actually does

| Store | Present behavior | What cannot yet be promised |
| --- | --- | --- |
| Native app | Explicit local-access removal clears identity/management recovery, local controller state and mesh identity. Confirmed account deletion attempts that cleanup; a protected deletion recovery receipt remains until server completion and successful local cleanup. | Uninstall is not a credential-erasure guarantee. Other controllers may retain their local data until they reconnect/remove access; account revocation is not remote disk erasure. |
| Link registry | Active account/device/host records and authentication/recovery history persist. Sign-in code validity is 10 minutes, access-token validity 15 minutes, refresh-token validity 180 days. | Those validity limits are **not deletion schedules** for registry records. No registry history/tombstone purge schedule was found. |
| KV abuse/legacy state | Rate windows last one hour, but each rate-limit KV write has a two-hour TTL; legacy OTP KV has 10 minutes. Filesystem KV expires on reads and has a startup/periodic sweep in the Node server. Legacy node secrets have no TTL and deletion explicitly removes them. | Matched deployed source schedules a startup/hourly sweep; housekeeping events were observed. Registry history is outside that sweep. Database backups and replicas remain unverified; see the deployed audit below. Native challenge records live in the registry, not the legacy expiring OTP KV. |
| Headscale | Account deletion expires preauth keys, removes nodes, deletes the exact associated user and verifies absence. | A failed or uncertain external write leaves deletion pending. Historical provider logs/backups are not removed by these calls. |
| Resend | Deletion removes the Link segment membership from the matching immutable contact ID. The shared global contact remains and is reported as `shared_contact_record`; sent-email history is not purged here. | Do not promise the whole contact is removed or infer an independent newsletter subscription from its existence. A Link-only contact's continued retention needs a decision/remediation, not an invented justification. |
| Sanity | Deletion removes current `siteEvent` documents matching both the account email and `source == leanzero-link`; it does not delete unrelated website events. | Transaction history, downstream email digests and backups are not erased by this implementation. |
| Service logs | Repository rotation script defaults to 30 days for rotated worker log archives. | The daily 03:17 rotation is installed/loaded, with last exit 0 and archive metadata corroborating activity. Its day-rounded `-mtime +30` predicate is not an exact 30-day erasure guarantee. Proxy/mesh/email-provider retention is unverified. |
| Completed deletion receipt | Email is blanked and live account records removed, but a registry tombstone remains under the hashed-email lookup, including account ID, revocation cutoff and deletion identifiers/hash/status/times. | No expiry/purge for this record is implemented. Hashed lookup is not anonymous. No legal retention basis is established by the code. |

Sources: [native cleanup](../../ui/ios/GooseRemote/App/ControllerStore.swift), [deletion service](../../leanzero-link/worker/src/controller/account-deletion.ts), [provider cleanup](../../leanzero-link/worker/src/controller/account-deletion-cleanup.ts), [authentication lifetimes](../../leanzero-link/worker/src/controller/crypto.ts), [KV cleanup](../../leanzero-link/worker/src/lib/fs-kv.ts), [KV configuration](../../leanzero-link/worker/src/lib/config.ts), [log rotation](../../leanzero-link/worker/ops/rotate-link-log.sh).

The implemented user path is Settings → Delete Link account → Email a deletion code → enter code → Permanently delete account → confirm. Accepted confirmation revokes account access immediately. The durable request can be checked after an interruption; `pending` is not `deleted`. There is no scheduled deletion retry worker: status requests resume cleanup. Unknown legacy/provider write outcomes stay pending until affirmatively reconciled under the [deletion runbook](../../leanzero-link/worker/ACCOUNT-DELETION-RUNBOOK.md). Never clear uncertainty based only on elapsed time or an empty list. This audit did not perform a live deletion.

Apple requires in-app initiation and account-associated data deletion, with legally required retention explained; email-code confirmation is permitted. A slower process must explain timing and confirm completion. The current retained-record categories and indefinite pending recovery therefore remain release questions: a disclosed retention category alone does not establish compliance, and a support link must not become a mandatory substitute for the in-app flow. [Apple account-deletion guidance](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion).

## Factual privacy-page draft

The following is ready as source-grounded draft copy; complete the owner/deployment fields below before publishing a policy.

Goose Remote connects your iPhone or iPad to sessions and jobs on your own Macs. LeanZero Link stores your email address and account, device and connection records so that you can sign in, discover your computers and manage access. Email sign-in and account-deletion codes are sent through Resend. The configured mesh infrastructure processes the keys and network information needed to connect your devices.

Session messages and management requests go to the Mac you select. That Mac runs the work and stores downloaded models. Its configured AI service may receive your messages and session context; using a cloud provider can therefore send content beyond your own devices. The app also saves protected drafts, session snapshots and delivery-recovery information locally. Provider credentials you enter are sent to the selected Mac and may remain in protected local recovery storage while the request is unresolved.

You can remove local access, revoke a connected device or initiate deletion of your Link account from the app. Account deletion removes connected-device access and cleans up the applicable Link and mesh records. It does not erase projects, model files or session databases on your Macs. If cleanup is interrupted, the app retains a recovery reference and lets you check the request. Some security receipts, shared contact records and historical service records currently remain; their precise purpose, permitted retention and deletion schedule must be completed before this text is published.

These are factual/policy inputs, not text the source can invent. Apple requires an accessible in-app and metadata privacy-policy link and clear retention/sharing disclosure; personal-data sharing with third-party AI requires explicit permission. Verify the real consent flow before shipping. [App Review privacy rules](https://developer.apple.com/app-store/review/guidelines/#privacy).

## Support copy and operating procedure

Draft user-facing copy:

Your work runs on the selected Mac. That Mac must be online and signed in to a compatible Goose Swarm version. If it goes offline, saved activity may be out of date; reconnect or use manual sync to check again. An uncertain message delivery is not a failed message: keep its command reference and check status before sending another copy.

To remove one device, revoke its access and remove its local data. To delete the Link account, open Settings and use Delete Link account. Confirm with the code sent to your account email. If the app says cleanup is pending, use Check deletion status; do not treat that status as completed deletion. Your Mac's projects, model files and session databases are separate from your Link account.

For support, the current app links to office@leanzero.net. Include app/build, iOS/iPadOS version, affected feature, approximate failure time and the command or deletion request reference. Do not include passwords, email codes, API keys, full transcripts or private project paths. Confirm inbox ownership/coverage and the public support URL before publishing this contact as the service commitment; no response-time promise is made here.

Operator procedure: query the original Mac's command receipt; distinguish accepted, delivered, rejected and terminal failure. Delivered does not mean the model complied. For a missing node inspect discovery, host lease, mesh membership/liveness and version compatibility separately. Do not reset account-wide credentials or host identity to repair one controller. A pending deletion follows the runbook and preserves its receipt; an unknown provider write is not safely fixed by retrying a second CREATE.

Before updates prove the oldest supported client with the additive backend, storage migration, credential recovery, duplicate delivery, partial sync and original-owner continuation. For incidents retain minimal redacted evidence, reproduce on the affected release and independently review the fix. A paused App Store rollout does not downgrade installed apps; a correction requires a newer version or compatible service repair. Preserve the approved archive and matching dSYMs at the recorded release-artifact location. [Apple version updates](https://developer.apple.com/help/app-store-connect/update-your-app/create-a-new-version), [phased-release controls](https://developer.apple.com/help/app-store-connect/update-your-app/release-a-version-update-in-phases).
